## 1. Static, Dynamic, Strong, and Weak

> [观看本课](https://dometrain.com/take/course/from-zero-to-hero-reflection-in-dotnet-2871274/static-dynamic-strong-and-weak-58128580/) · 4:21

### 总结

C# 是一门静态类型且强类型的语言,这意味着类型在编译时确定,并且类型系统会被严格执行。
虽然这带来了安全性和可预测性,但某些场景需要在运行时以动态方式与类型交互。
反射是 .NET 中检查类型元数据(例如成员、方法和属性的名称)的主要机制,它让开发者能够处理那些在编译阶段可能并不完全已知或固定的类型。

### 核心概念

* **静态类型(Static Typing)**:变量的类型在编译时确定,并在其整个生命周期内保持不变。
* **动态类型(Dynamic Typing)**:变量的类型可以在运行时改变;虽然 C# 有 `dynamic` 关键字,但它本质上是一门静态语言。
* **强类型(Strong Typing)**:严格执行类型规则,对可能不安全的转换(例如 double 转 int)要求显式操作,比如强制转换(cast)。
* **弱类型(Weak Typing)**:较宽松的类型约束,允许类型之间进行更多隐式转换。
* **类型元数据(Type Metadata)**:关于类型结构的信息,包括方法、属性和参数的名称,可通过反射访问。

### 课程笔记

#### 静态类型与动态类型

C# 是一门静态类型语言,这意味着变量的类型在编译时就已知。
一旦变量被声明为某个特定类型,例如整数或字符串,它在整个生命周期内都会保持该类型。
这与 Python 这类动态类型语言不同,在那些语言中,变量的类型可以在运行时改变。
虽然 C# 确实包含一个引入了部分动态类型特性的 `dynamic` 关键字,但这门语言从根本上仍然是静态的。

#### 强类型与弱类型

C# 也被归类为强类型语言。
尽管对于"强"类型与"弱"类型并没有普遍公认的定义,但它通常指类型系统内部的执行严格程度。
C# 是严格的;例如,你不能把一个双精度浮点数隐式赋值给整数,因为这会导致精度损失。
这样的赋值需要显式强制转换。
相比之下,弱类型语言的约束更宽松,可能会隐式地允许这类赋值。

#### 反射的必要性

反射之所以必不可少,是因为它允许程序在运行时与类型元数据交互。
在编译时,编译器会确保类型是兼容的,大多数 C# 程序就是这样构建的。
然而,在某些情况下,程序需要在运行时以动态方式与类型交互。

反射是用来检查类型元数据的工具。
它允许程序按名称查找类型,或访问其成员的信息,例如方法名、属性或参数名。
虽然现代 .NET 引入了源生成器(source generator)等高级替代方案,但反射是在运行时检查类型元数据的历史悠久且最主要的工具。

## 2. Where does type information go?

> [观看本课](https://dometrain.com/take/course/from-zero-to-hero-reflection-in-dotnet-2871274/where-does-type-information-go-58128581/) · 3:30

### 总结

C# 是一门静态类型语言,类型信息在编译时就已知,但这些信息并不会在构建过程中丢失。
相反,编译器会把丰富的元数据与通用中间语言(Common Intermediate Language,CIL)一起嵌入到程序集(.dll 或 .exe 文件)中。
这些元数据包括类型名称、成员和继承层次结构,公共语言运行时(Common Language Runtime,CLR)会使用它们,而反射 API 则在运行时公开它们,以便动态地检查和操作类型。

### 核心概念

* **静态类型(Static Typing)**:类型信息由编译器借助源代码进行验证。
* **通用中间语言(Common Intermediate Language,CIL)**:表示已编译 .NET 应用程序执行流程的指令集。
* **程序集元数据(Assembly Metadata)**:存储在 DLL 和可执行文件中的数据,描述代码中定义的类型、成员及其关系。
* **公共语言运行时(Common Language Runtime,CLR)**:利用程序集元数据来管理代码执行的执行引擎。
* **反射(Reflection)**:在运行时用于查询并操作嵌入在程序集中的元数据的 API。
* **源生成器(Source Generators)**:反射的一种编译时替代方案,它执行元数据分析,在最终二进制文件生成之前生成额外的源代码。

### 课程笔记

#### 编译过程与元数据

在 C# 中,类型在编译时就已知,这使它成为一门静态类型语言。
在构建过程中,编译器可以访问完整的源代码,但最终二进制文件中交付的并不是这些原始源代码。
相反,编译器会把源代码转换为通用中间语言(CIL),其中包含应用程序执行流程的指令。

不过,一个程序集(.dll 或 .exe)包含的不只是 CIL。
编译器还会嵌入一整套元数据,描述程序中使用的每一个类型。
这确保了编译器可用的信息以结构化的格式被保留下来,在应用程序部署之后仍然可以访问。

```text
  源代码
     |
     v
  编译器
     |
     v
+------------------------------+
| 程序集 (.dll / .exe)         |
|  +------------------------+  |
|  | CIL (执行流程的指令)   |  |
|  +------------------------+  |
|  | 元数据 (描述每个类型)  |  |
|  +------------------------+  |
+------------------------------+
```

#### 程序集元数据的内容

.NET 程序集中包含的元数据非常详尽。
它包括:
* **类型名称**:类、结构体、枚举和接口的完整名称。
* **成员名称**:属性、方法、字段和事件的名称与签名。
* **关系**:关于继承(基类)和接口实现的信息。

正是这些元数据让公共语言运行时(CLR)能够正确地理解并执行代码。

#### 反射如何利用元数据

反射是一种机制,让开发者能够在运行时与这些嵌入的元数据交互。
标准的执行流程遵循 CIL 指令,而反射则允许应用程序"侧过头去看"元数据,从而:
* 通过字符串名称查找类型。
* 发现并检查某个特定类型的属性和方法。
* 动态地实例化类型或调用成员。

在编译时无法获得具体类型信息的场景下,这一点尤其强大,它让代码结构可以非常灵活和通用。

#### 反射与源生成器

虽然反射是一项运行时技术,但 .NET 也支持源生成器。
源生成器执行类似的元数据分析,但它们是在编译时进行的,用于生成额外的 C# 源代码。
虽然两者在功能上有重叠,但在需要运行时动态性且无法进行编译时生成的场景中,反射仍然是必不可少的。
